# songloft-org/songloft#518: playlist browsing

The [Issue](https://github.com/songloft-org/songloft/issues/518) requests title initials, mobile home grids or vertical browsing and counts. The user also asks for comparable Flutter / Lynx behavior and configurable wide-screen Lynx grids. [中文](../../project/issue-518.md).

## Behavior

- A home menu offers automatic, carousel, grid and vertical list layouts; every mode displays song counts. Automatic preserves narrow carousels and wide grids.
- Settings → Appearance → Home playlist layout offers automatic / 2–6 columns and 1–4 / all rows. Columns fit each actual section, including desktop bento halves; row budgets use the reduced count. Each layout fetches enough pages for its budget; lists and all rows cap at 200 items per section. View all opens the complete collection. Preferences stay on this device, and late reads cannot overwrite new choices.
- Both clients offer Show radio section in Settings → Appearance, enabled by default and stored on this device. Turning it off hides the entire My Radios home section and excludes its loading/errors and automatic pagination. The Lynx wide-screen playlist section uses the full row and defaults to six columns for a single section, reduced when needed. Settings can enable it again.
- Details retain numbers and show initials at contiguous group boundaries: pinyin for Chinese, uppercase Latin letters and `#` for other scripts, digits and symbols. Titles, order, playback indices, selection and manual sorting retain their semantics.
- A scrollbar outside the virtual list shows the current initial, title and position / total. Unloaded destinations fetch pages on demand; ordinary opening stays paginated. Empty pages, errors, navigation and filter changes stop old positioning operations.
- The pure JS `pinyin-pro` dependency is credited on the licenses page. Native modules and backend APIs are unchanged.
