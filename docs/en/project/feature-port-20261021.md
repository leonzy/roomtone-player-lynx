## Behavior

| Feature | Result |
|---|---|
| Preference sync | Pull `/settings/user-preferences` after login; synchronize theme, playback mode, playlist view, quality, cache cap and volume. Seed an all-default server from local settings; debounce and serialize edits. Reject stale sessions and failed-read default overwrites; retry on edits or foreground return. Retain the backend's existing server-wide setting semantics. |
| Permanent ordering | Confirm name ascending/descending, numeric prefix or shuffle in the playlist menu; call the server action and invalidate song/detail queries. Local view sorting remains separate. |
| Mini player | Playback settings select play/pause only, previous/next, or previous/next plus playback mode. Updates live and persists locally. |
| Deletion options | Explicit opt-in to delete local files or songs belonging only to deleted playlists. Default off, reset per target; removing membership offers no file deletion. |
| Keyboard bindings | Record eight Web actions, detect conflicts and reset defaults. Includes seeking and mute; persists locally and protects inputs, IME, browser keys and overlays. |
| MV subtitles | Current synchronized lyric and translation remain visible independently of controls, with word highlighting and a local subtitle toggle. Android/iOS/HarmonyOS surfaces consume the shared page and retain the existing player. |
| Web fullscreen | Fullscreen the root containing video, lyrics and controls. A real click retry handles expired browser activation; Escape updates state and video exit cleans up owned fullscreen and stale requests. |
| Smooth lyrics | Only the active line extrapolates at about 30Hz; follows speed, seek, pause/buffer and track changes. Stop after one second of stalled progress, in background or on unmount; honor reduced motion. |
| Home widgets | Android resizable RemoteViews show metadata/artwork, transport and favorite controls using the current queue. iOS adds small/medium WidgetKit targets; control links open the app to execute actions. Update on snapshot changes, not progress; persist a local thumbnail rather than authenticated artwork URLs. |

## Optional host contract

- Android/iOS `SongloftPlatform.updateHomeWidget(json: string): void` receives `hasSong/title/artist/coverUrl/isPlaying/isFavorite/canNext/canPrev`. `consumeWidgetAction(callback)` consumes the cold-start action after JS installs its listener. `SongloftWidget.action` sends `[{action}]`; actions are `open/toggle/previous/next/favorite`. Missing old-shell methods are skipped; no HarmonyOS/Web home widget in this batch.
- Web `SongloftVideo.fullscreenState(json, callback)` and `setFullscreen(json, callback)` return JSON `{supported, active, needsGesture?}`. `SongloftVideo.fullscreenChanged` sends `[{supported, active}]`. Required video methods remain unchanged.
- All four hosts add optional `SongloftLifecycle.paused`; lyrics also consume existing `resumed` and clean up subscriptions. Older shells retain their prior behavior.
- Both iOS targets need App Group `group.org.songloft.lynx` in their signing profiles. Linux project parsing does not validate an Apple build or signing.
